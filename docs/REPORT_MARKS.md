# Aristos Council — Marks on a Report

Every annotation you can meet on an Aristos output — a ranked table, a Company Check, a
snapshot note, a narrated report — in one place. For each: the **exact mark as rendered**,
**what fired it**, and **what it does *not* mean**. The theme throughout: these marks
*disclose*; they never silently change a number or a verdict. Sources in
`src/aristos_council/` are named per row.

| Mark (as rendered) | What fired it | What it does **not** mean |
|---|---|---|
| `[⚠ price diverging: +35% 12m — cyclical inflection or mania; human review]` | An **excluded** name has a CONFIRMED fundamental-criterion FAIL **and** trailing 12-month momentum **≥ +0.30**. The actual momentum is shown. (`factors.price_divergence_flag`) | **Not a direction call.** It marks *disagreement* — price ran up while a quality floor failed — never the sign of the next move; it also decorates value traps still falling. It never alters a verdict or an exclusion. |
| `[⚠ narration check: "…" contradicts rank table — table is authoritative]` | The LLM narrative made an ordinal/superlative claim (best, worst, top-, bottom-) that the deterministic rank table contradicts. (`narration_check.py`) | **Not a rewrite.** The prose is left exactly as written and the verdict is untouched — the line annotates the contradiction and defers to the table. |
| `[borderline]` | A confirmed FAIL whose observed value is within **5% (relative)** of its threshold, e.g. `screen: min_roic (observed 0.1198 vs threshold 0.12) [borderline]`. (`factors.is_borderline_fail`) | **Not a pass, not a softened floor.** A borderline fail is still a fail; the tag only flags a knife-edge miss to the reader. |
| `(=21.0 — tie broken alphabetically)` | A ranked name shares its combined rank-sum with the name **directly above it** *and* received a **different verdict** — i.e. the tie straddles a verdict boundary, and the deterministic alphabetical tie-break decided which side each fell on (MRK/PG both 20.0, HOLD/SELL → PG annotated). (`pipeline.tie_boundary_notes`) | **Not a quality distinction** between the tied names, and **not on every tie** — a tie inside one verdict band needs no disclosure, so none is emitted. Display-only: the ordering, the cut, and the verdicts are all unchanged. |
| `(tied)` (inside a position cell, e.g. `#3 of 9 (tied) · score 14 (best 3 · worst 27)`) | Another ranked name shares this name's combined rank-sum, so they **share** the cohort position (competition ranking). (`rank_engine.format_position_cell`, RANK-DISPLAY-1) | **Not a missing position.** Shared positions are the point — the ordinal leads the cell so the rank-**sum** ("score") is never misread as a position; `best`/`worst` give the score its scale. |
| `[static: 2026-06-01, Schwab factsheet]` | An ETF factor value (expense ratio / fund size / distribution yield) was served from the **committed static layer** because the vendor's value was missing or implausible. The receipt carries the verification date and the named source. (`etf_static.StaticRow.tag`, ETF-STATIC-1) | **Not a guess and not a vendor value.** It is a *receipt*, like the FX one — a human-verified factsheet number, dated, replayed byte-identically from a committed CSV. Vendor values always win where present and plausible, so a static tag means the vendor had nothing usable. |
| `static data stale — refresh required` | A static entry's `as_of` is more than **90 days** old, or unparseable. (`etf_static.STALE_NOTE`) | **Not a filled value.** The field is **withheld** — the factor abstains and the note is surfaced instead. Stale static data is never served silently, and an unverifiable freshness is treated as stale. |
| `asset kind 'ETF' outside this strategy's scope` | A confirmed vendor `quoteType` puts the name outside the lens's declared `asset_kinds` — a fund in a stock lens, or an operating company in an ETF lens. Fired **before** screen, cap, sector, and factor paths. (`factors.is_asset_kind_out_of_scope`, ETF-1) | **Not a judgment on the name** and not a data gap. It is the wall between asset classes: a vendor serves look-through "fundamentals" for an index tracker happily, so the alternative to this exclusion is quiet garbage. Confirmed-only — a **missing** `quoteType` never gates. |
| `†` (suffix on a ranked row) + footnote `† PEP — screen criterion not evaluated: max_payout_ratio_fcf (mean FCF ≤ 0)` | A **ranked** name passed the screen while one screen criterion could not be evaluated (abstained). (`pipeline.ranked_abstention_footnotes`) | **Not a failure or an exclusion.** Abstention never excludes — the name qualified; the footnote just makes the un-evaluated check visible. |
| `[gating]` / `[non-gating]` (Company Check screen rows) | Derived from the **enforcing runner**: `[gating]` if a confirmed fail of this criterion would cap the disposition at SELL; `[non-gating]` if this evaluation cannot exclude/cap (e.g. it only abstains here). (`company_check`) | **`[non-gating]` does not mean "unimportant".** It means *this evaluation cannot exclude the name* — it's about enforcement, not weight. |
| `[ev, DKK→USD @ 0.1452 (2026-07-10)]` | A foreign issuer on a US listing: the EV earnings-yield was computed **after converting** debt/cash/EBIT from the accounts currency to the price currency at the shown rate and date. (`factors.CurrencyConversion`, VERIFY-2) | **Not an FX opinion.** It's a *receipt* — proof the conversion happened and at what rate, so a mixed-currency figure can't hide. On a failed FX fetch the factor **abstains** rather than mix. |
| `[computed]` · `[ev]` · `[fallback:pe]` · `[fallback:ebit_mcap]` · `[fallback:dividend_yield]` · `[abstained]` | The **basis tag** — which computation path produced a factor value. `ev` = true EBIT/EV; `fallback:pe` = EV components missing, used 1/PE; `fallback:dividend_yield` = buybacks unavailable, used dividend yield; `abstained` = not computable. (`factors` source tags) | **Not a quality score.** A fallback tag discloses a *coarser basis*, not a bad number — it exists so a proxy never masquerades as the real thing. |
| `*` (on a factor rank in the ranked table) | Under `missing: neutral`, a name lacking one factor value has that factor's rank **imputed** from the mean of its present ranks (judged on what it has). (`rank_engine`) | **Not a computed value.** The `*` marks a filled-in rank that neither helps nor hurts the name on the absent factor. |
| `dividend_yield 0.2393 (>15%) — vendor value implausible — flagged` | A cheap boundary sanity check caught an absurd vendor value: dividend yield > 15%, negative market cap, unit-confused debt/equity (> 10000), P/B > 100, or ROE > 300%. (`data.adapter.implausible_fields`, VERIFY-2 / FIN-1) | **Not a correction or a failure.** The value is flagged and **withheld from narrator evidence** — never silently fixed, never used to fail a name; it surfaces in Company Check's DATA INTEGRITY. |
| `Shortlist — 2 of 21 BUYs survived the checks` (a report section, and a clause on the summary line) | The names the **primary selector** rated BUY that no **check** lens rated SELL and whose valuation sits below the 80th percentile of their own history. DERIVED from the grid below it. (`pipeline.shortlist`, SHORTLIST-1) | **Not a recommendation and not a new judgement.** Nothing is re-graded, re-ranked or re-weighted — every input is a verdict or a percentile the run already produced. An empty shortlist WITH drop reasons is a RESULT (the checks removed everyone), and reads differently from the section stating a `reason`, which means no list could be formed at all. |
| `⚠ Magic Formula RAW is a value lens; this list is marked income. Its verdicts answer a different question than the list was built for.` | The list declares a `thesis` and the PRIMARY lens's own `thesis` does not include it. (`pipeline.cohort_fit_line`, THESIS-1) | **Not a block and not a filter.** The run proceeds, the lens stays in every picker, and the verdicts are honest — they simply answer a question the list was not built around. Silent when the list is unmarked, when the lens declares no thesis, or when they match. |
| `ℹ Forensic is a check lens; it doubts, it does not select. Pick a selector as primary for a shortlist.` | A lens whose `kind` is `check` was chosen as PRIMARY. (`pipeline.cohort_fit_line`, KIND-1) | **Not an error.** A check lens ranks and reports normally; it just cannot produce a shortlist, because its SELL is a doubt about someone else's pick rather than a rejection of its own. |
| `Cheap and good: high profit on the money invested, a low price for that profit, and a rising share.` (one line under a lens's name) | The lens's `asks` — what it wants of a company, in one plain-English sentence. Rendered in the Run tab and under every lens heading in both reports. (`pipeline.lens_asks`, CAPTION-1) | **Not a rule and not a threshold.** It is the QUESTION the lens answers, so a verdict can be read for what it means. A lens whose YAML declares no `asks` renders no line at all. |
| `the dividend was cut in 2021: the year's total fell 33% and the typical payment fell 33% against 2020` | A year in the window where **both** the total paid and the typical (median) payment fell more than 10% against the prior year. Both figures are named because either one alone is unreliable — a missing payment or a special moves only the total, a cadence change moves only the typical payment. (`screening._cuts_from_year_stats`, CRIT-NOCUT-2) | **Not a judgement about why.** A deliberately variable payout (Equinor's extraordinary tranche, Petrobras) will read this way in the year the variable part falls, and the arithmetic is correct when it does — the lens is for payers whose dividend is meant to hold. The sentence reports the fall; it does not claim the company is in trouble. |
| `no year paid less than the year before, across the last 5 complete years` (a rule's *limit* column, where every other row reads "at least 1.5%" or "at most 80%") | The criterion's threshold is a **window**, not a cap on the measured value: `max_dividend_cuts` measures a cut SIZE against a count of YEARS, so the generated phrase would compare a percentage to a year count. Such a criterion states its own rule phrase. (`registry.Criterion.threshold_text`, CRIT-NOCUT-1) | **Not a missing threshold.** The rule is exact and the window is the number a strategy sets; it simply cannot be written as "at most N" without comparing two different units. The observed value in the exclusion sentence is still a number — the size of the largest cut. |
| `Summary` (a report section of five short paragraphs, above everything else) | The plain-English summary tick-box was on and the written note passed every check. Composed by a language model from a facts pack built out of the run's own tables — never from the report — and placed first because it explains the rest. (`reader.py`, READER-1) | **Not a recommendation and not an analysis.** It reports what the run found, in the run's own numbers; the advice vocabulary is refused outright and every figure in it was matched back to the tables before it was published. It adds no information the sections below do not already carry. |
| `Summary withheld: number not in the facts: 120` · `Summary withheld: name not in the run: XOM` · `Summary withheld: role mismatch: …` · `Summary withheld: unanimous BUY not mentioned: …` | The summary was written and then FAILED one of the **four** checks that can withhold it, plus the empty-field shape check. Every one of them means the prose contradicts the run. (`reader_check.py`, READER-5) | **Not a style verdict.** READER-5 removed the advice-word ban, the gloss rule, the vague-range rule, the nested-bracket rule and the 300-word hard stop from this list: of the first five live summaries, four were destroyed by a missing bracket and not one for saying anything untrue. Those faults are still detected and recorded on the run as `meta.reader.notes` — they just no longer cost a reader the whole summary. |
| `meta.reader.notes = ['term without gloss: momentum', '318 words (target 300)']` (run meta; never rendered in the report) | A style fault the prompt asks the writer to avoid: over the word target, an advice word, a term used without an explanation, a vague range, a bracket inside a bracket. (`reader_check.ReaderCheck.notes`, READER-5) | **Not a reason to withhold, and not shown to a reader.** It is the evidence for whether the prompt's style rules are working — which is the only thing they were ever able to tell us. Before READER-5 a style fault either destroyed the summary or vanished without trace, and neither taught anyone anything. |
| `Summary not written: no API key` | The tick-box was on but no key was available, so no call was made. (`reader.NO_KEY_NOTE`) | **Not an error.** The run is complete and free; only the optional note is missing. |
| `#2 of 43 · BUY · ranked on 2 of 3 factors` (a verdict-grid cell) | The lens scored this name on FEWER factors than it has, because one abstained and the lens's `missing: neutral` policy imputed it from the ranks that were present. The marker is muted and sits AFTER the verdict, which keeps its colour and its word. (`pipeline.MultiStrategyCell.factor_note`, FACTOR-MARK-1 / FACTOR-MARK-2) | **Not a downgrade and not a lower-confidence verdict.** The rank is exactly the one the lens computed; judging a name on what it has beats dumping it for a gap. The marker exists because that decision was previously invisible — 37 cells in the Forensic column of the 2026-09-16 oil run carried it. It is also **not a reason to lose the colour**: before FACTOR-MARK-2 a marked cell fell out of the verdict palette entirely, so the disclosure cost its own subject the grading. |
| `the dividend was cut in 2021: the year's total fell 33% and the typical payment fell 33% against 2020; the rule requires no year paid less than the year before, across the last 5 complete years.` (an exclusion sentence) | A criterion that writes its OWN reason has it printed verbatim, with the report's rule clause after it. Only `max_dividend_cuts` declares this, because only it knows something the generated clause cannot express — the YEAR, and that BOTH measures fell. (`registry.Criterion.observation_from_note`, NOCUT-3) | **Not a different arithmetic.** The same year, the same falls, the same exclusion; the generated clause ("the largest fall was 33% of the prior year's total") simply named no year, so there was nothing a reader could go and check. A criterion that cannot say which year falls back to that clause rather than printing nothing. |
| `implied move +322% exceeds the upper sanity bound (+150%) — inputs suspect (a thin EBIT year, a share-count or a currency mismatch); not stated` · `implied move -98% falls past the lower sanity bound (-75%) — …` | The reversion value crossed one of the two sanity bounds and ABSTAINED. Each wording names the bound that fired, with that bound's own number, and the suspect profit line is the BASIS's own — "a thin earnings year" on the P/E route, where there is no EBIT in the arithmetic at all. (`reversion.GAP_SANITY` / `GAP_SANITY_DOWN`, BAND-3 / REV-BOUND-1 / REV-BOUND-2) | **Not a clamp and not a symmetric bound.** The value is withheld, never shrunk. The two bounds are different sizes on purpose (an implied price cannot fall past -100%, so a symmetric 150% could never fire downward) — which is why the old single wording, quoting "±150%" beside a -98% move, disproved itself. The band keeps its percentile either way. |
| `**Dividends vs free cash flow** `max_payout_ratio_fcf` · rule: at most 80% of 4-year average free cash flow · **27 names**` (a heading in a lens's detail section) | The per-lens detail section groups excluded names by the RULE that removed them, largest group first, and states each rule once. Under it: what the rule is FOR (`Criterion.why`) and a table of the names, each with the value it was measured at, worst miss first. (`pipeline.lens_detail`, DETAIL-1) | **Not a re-grading and not a summary that hides names.** Every name, reason and number is the one the run recorded — grouping decided where each is PRINTED. The per-name sentence still exists, is unchanged, and is what the CLI and Company Check print. The criterion id stays beside the label, as it did on every bullet before. |
| `▸ **Company size** · rule: at least $5.0bn (applied before the screen) · **30 names** (no other rule was tested on these)` (a collapsed block) | A PRE-SCREEN gate — the size floor, the sector gate, the asset-kind gate. It ran before the screen, so its names were never tested on any rule below it. Gates come first regardless of size and fold away behind their own summary; printing forces them open. (`pipeline.lens_detail`, DETAIL-1) | **Not a hidden exclusion.** Every name is listed, one click away, with the gate's own limit read from the strategy that ran. The caveat is the point: their absence from every rule group below is an artefact of the ORDER, and a reader not told that would read it as evidence. |
| `Where the numbers came from` — a table of Factor / Real data / Abstained, e.g. `Dividend coverage | 41 of 43 | 2 — 4-year mean free cash flow ≤ 0 (Crescent Energy, AltaGas)` | The same per-factor counts the section previously stated as one sentence each, as a table — plus the NAMES of the abstainers, which the sentence form only counted. (`pipeline.lens_detail`, REPORT-1 / DETAIL-1) | **Not a quality score.** An abstention is a measurement that could not be made, never a bad reading and never a fail. The counts are unchanged; only the shape is. |
| `Summary withheld: …` after TWO attempts (`meta.reader.attempts = 2`) | The written summary failed its check, was rewritten once with the check's own complaint in front of the writer, and failed again. Both checks are recorded in the run meta. (`reader.MAX_ATTEMPTS`, READER-3) | **Not a retry loop.** Exactly one retry: a second failure of the same deterministic check, with the problems written out, will not be found on a third pass. The facts pack is identical between attempts — the retry may reword, never be given more to say. |
| `⚠ priced high: 99th percentile of its own 5-year range` (a Note on a kept shortlist row) | The name was rated BUY by **every** lens in the run, and the valuation band would otherwise have dropped it. The band is a separate check, not one of the lenses, so it does not eliminate a unanimous pick — the name is kept and the percentile that would have removed it rides on its row. (`pipeline.shortlist`, SHORTLIST-2) | **Not a verdict, and not an endorsement of the price.** Every lens read the same recent years, so their agreement is not independent evidence that the price is justified — which is why the section says so under the table. One HOLD anywhere, or one lens that never ranked the name, and the band drops it as before. |
| `Shortlist — 1 of 9 BUYs survived the checks (1 with a price warning)` | The section title, and the same clause on the run's summary line. The warning count is appended wherever the shortlist is counted. (`pipeline.Shortlist.caution_clause`, SHORTLIST-2) | **Not a second list.** The cautioned names are ON the shortlist and in the primary's rank order; the count exists because a total that hides a warning is the one outcome the unanimous exception must not produce. Absent when no row carries a warning. |
| `Summary withheld: role mismatch: Magic Formula RAW called a check` | The summary NAMED a test and described it as a check or a picker, and the pack says it is the other. (`reader_check`, READER-4) | **Not a style note.** A reader told a picker is a check reads its BUYs as "nothing objectionable found" rather than "this test chose it", which inverts what the run said. (`reader_check`, READER-4) | **Not pedantry about punctuation.** A gloss exists to be read, and one that needs its own gloss has failed — this exact string is what the bracket rule produced live, and it is less legible than the word it was explaining. | `Summary withheld: unanimous BUY not mentioned: Suncor Energy Inc.` | A name every test rated BUY was not named anywhere in the summary. (`reader_check`, READER-4) | **Not a demand for a recommendation.** It is the strongest agreement a multi-test run can produce, and the pack says what became of the name — on the shortlist, on it with a price warning, or dropped and why. | `⚠ +80% 12m` (a Note badge in a lens's detail section) | The share price has risen 80% over the last twelve months, and the report attaches the badge whenever the rise is more than +30%. (`glossary.DETAIL_BADGE_NOTE`, DETAIL-1b) | **Not a direction call and not part of the rule the company failed.** A move that large in a cyclical company means either the cycle has turned and profits are about to catch up, or the price has run ahead of anything the business can earn. | `UNRATEABLE: no data — possibly delisted` | A ticker with failed fundamentals **and** no usable price history (a delisted / all-404 name). (`company_check`, Spec 4D) | **Not a fresh verdict.** Company Check never issues one for a single name — this is a *reported historical fact* from a past universe run, never recomputed from live data. ## Narrator guardrails

The LLM layer **narrates the deterministic verdict; it never decides one.** Four disciplines
keep the prose honest, and each is enforced in code, not merely requested in a prompt:

- **Rank-semantics legend.** The narrator is handed an explicit legend — *rank 1 = best on
  every factor; lower combined rank-sum = better; N = <cohort size>; ordinal claims (best,
  worst, second-, top-, bottom-) must be derived only from the rank table.* A post-check
  (`narration_check.py`) **annotates, it does not rewrite**: when the prose contradicts the
  table it appends the `[⚠ narration check: …]` line above, quoting the model's *original*
  wording (markdown included) and leaving the prose exactly as written — the table is
  authoritative. The check is deliberately conservative about what counts as a claim: hedged
  ("near-best"), negated ("not the best"), theoretical ("worst possible = 48"), and
  value-rather-than-rank superlatives ("exceptional momentum") are left alone, and an ordinal
  binds to the factor its own clause **names**, never to a column position.
- **Quarantined headline FCF.** The vendor's headline (TTM) `free_cash_flow` can embed
  one-off cash events (NVO printed −12.04B beside a positive annual series). It is withheld
  from the narrator's evidence and annotated *"ttm_incl_one_offs — do not use for
  sustainability claims; cite `free_cash_flow_annual` instead"*, so the only citable FCF
  basis is the annual series the screens use.
- **Open questions are not findings.** Anything the narrator cannot ground in the evidence
  is confined to an `OPEN QUESTIONS (unresolved, for human review — not facts)` block — it is
  never asserted as a finding, and forward deterioration is never stated as fact.
- **Narration explains, it does not judge.** The verdict of record is the deterministic
  ranker's; the header states the division of labor plainly (*Verdict: deterministic ranker.
  Narrative: LLM (non-judging).*), and no narrator output can change screen, rank, or gate.

## Cohort graded (exact membership)

Every run record — the markdown a run tab writes and the one it auto-persists — ends with a
section naming the cohort it actually graded:

```
## Cohort graded (exact membership)

- list: `my_portfolio_v1` · 23 names · members `3f9c1ad2`

AAPL, MSFT, NVDA, …
```

**What fired it.** A saved list is a plain, EDITABLE ticker list (FUND-UI-2), so an id alone
dates badly: `my_portfolio_v1` in June and in August can be different cohorts. A rank verdict is
also universe-relative — a name's position is a statement about the names it was ranked *against*.
So the pipeline stamps `universe_members` (the exact list as run) and `universe_member_hash` (an
order-insensitive `hex8` over the normalized, de-duped set — `universe.member_hash`) onto every
run's `meta`, and this section renders them. A multi-lens grid grades one cohort under N lenses,
so it carries **one** such section.

**What it does not mean.** The member list is what went **IN**, not what survived: names that were
excluded by the screen or came back UNRATEABLE are members too, because the cohort a name was
ranked against includes them. The hash is not a version number and there is no versioning ceremony
in the UI — nothing prompts you, nothing is bumped; it is recorded silently and is simply what
makes a past run interpretable after the list moved on. A record written **before** FUND-UI-2
carries no members, and then **no section is emitted at all** — an empty block would imply nothing
was graded.
